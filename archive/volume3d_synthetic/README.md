# Module 3 — 부피·무게 탐지 (3D 모델링)

드론이 쓰레기 하나를 발견하면 그 주위를 한 바퀴 돌며 촬영한다. 이 모듈은
그 멀티뷰 사진들을 입력받아 ① 3D 구조를 복원하고 ② 부피를 계산한 뒤
③ 재질별 밀도를 곱해 무게를 추정한다. 다른 모듈(영상 수신/맵핑, 객체
탐지, 수거 계획)과는 독립적으로 동작하며, 입출력 계약만 맞으면 나중에
그대로 이어붙일 수 있다.

## 입출력 계약

- **입력**: 물체 주위를 돈 사진 여러 장이 담긴 폴더 (최소 15~20장 권장,
  연속 프레임 간 겹침이 많을수록 좋음)
- **출력**: 부피(L, m³) + 재질별 추정 무게(kg) + 포인트클라우드/메시 파일

## 파이프라인

1. `reconstruct.py` — pycolmap으로 SfM(Structure-from-Motion) 복원.
   특징점 추출 → 전수 매칭 → 증분 복원 순으로 카메라 포즈와 희소
   포인트클라우드를 얻는다.
2. `estimate_volume.py` — 포인트클라우드의 convex hull(볼록 껍질)
   부피를 계산하고, 재질별 겉보기 밀도를 곱해 무게를 추정한다.

```bash
python reconstruct.py <사진폴더> <작업폴더>
python estimate_volume.py <작업폴더>
```

## 검증: 실제 드론 데이터가 아직 없어서 합성 데이터로 먼저 검증

회사에서 받은 데이터는 정사영상(위에서 내려다본 2D 사진) + 쓰레기
크롭 이미지뿐이라 실제 멀티뷰(여러 각도) 사진이 없다. 그래서
`make_synthetic_object.py`로 "정답 부피를 아는" 가상의 스티로폼 상자
(0.4m × 0.25m × 0.2m = 20L)를 만들고, 그 주위를 도는 32개의 가상
카메라로 사진을 찍어 파이프라인 전체를 검증했다.

```bash
python make_synthetic_object.py   # data/synthetic_box/ 생성
python reconstruct.py data/synthetic_box/images data/synthetic_box/colmap
python estimate_volume.py data/synthetic_box
```

### 검증 결과

| 항목 | 값 |
|---|---|
| 정답 부피 | 20.00 L |
| 복원 후 추정 부피 | 24.07 L |
| 오차 | +20.4% |
| 카메라 등록 성공률 | 23 / 32장 |
| SfM 포인트 수 (이상점 제거 후) | 3,518개 |

20% 내외 오차는 sparse SfM + convex hull이라는 간단한 조합치고는
합리적인 수준이며, 실물 적용 전에 "파이프라인 자체가 동작한다"는 것을
확인하는 것이 이 검증의 목적이다.

### 과정에서 확인한 문제와 해결

- **체커보드 무늬는 안 된다**: 처음에 특징점 매칭용으로 체커보드 무늬를
  입혔더니 칸들이 서로 구별이 안 돼서 32장 중 2장만 카메라로 등록되고
  복원이 사실상 실패했다. 무작위 반점(speckle) 무늬로 바꾸자 23장이
  등록됐다. → 실제 드론 촬영 시에도 무늬 없는 매끈한 표면(흰색
  스티로폼 등)은 특징점이 부족해 복원이 어려울 수 있다는 뜻이므로,
  필요하면 보조 조명/각도 다양화로 대응해야 한다.
- **스케일(크기) 문제**: 사진만으로 하는 SfM은 상대적인 모양만
  복원하고 실제 크기(미터 단위)를 모른다. 이 검증에서는 합성 데이터를
  만들 때 기록해 둔 "진짜 카메라 위치"로 스케일을 역산했는데, 실제
  드론에서는 **Module 1에서 기록하는 GPS/IMU 궤적**이 이 역할을 대신
  해야 한다 — 즉 Module 1과 Module 3는 독립 모듈이지만 무게 추정의
  정확도를 위해서는 결합이 필요하다.
- **이상점(outlier) 제거가 필수**: SfM은 잘못 매칭된 특징점으로 물체에서
  멀리 떨어진 이상점을 만들어내고, 이 점 하나가 convex hull 부피를
  크게 부풀린다(이상점 제거 전 오차 +146% → 제거 후 +20%). 통계적
  이상점 제거(`remove_statistical_outlier`)를 부피 계산 전 필수
  단계로 넣었다.

### 재질별 밀도 가정

실제 폴리스티렌 밀도(1.05 kg/L)가 아니라 **발포/겉보기 밀도**를 쓴다
(스티로폼 내부가 대부분 공기이기 때문):

| 재질 | 밀도 (kg/L) |
|---|---|
| STY (스티로폼) | 0.02 |
| PLA (플라스틱 용기) | 0.35 |
| ROP (로프) | 0.40 |
| FIS (폐어망) | 0.15 |

(회사 라벨 데이터 분석 결과 `weight_kg = 면적 × 재질별 고정계수`로,
실측이 아닌 2D 면적 기반 추정이었음을 이미 확인했다 — 이 모듈의 3D
부피 기반 추정이 그보다 더 정확한 대안이 되는 것이 프로젝트의 핵심
주장이다.)

## 한계와 다음 단계

- Convex hull은 오목한 형상(예: 구겨진 그물, U자형 쓰레기)에서는
  부피를 과대평가한다. 더 정밀하게 하려면 알파쉐입(alpha shape)이나
  Poisson 표면 복원으로 바꿀 수 있다.
- 실제 드론 영상(Mini 5 Pro 녹화본)을 프레임 추출해 이 파이프라인에
  넣어보는 것이 다음 검증 단계.
- Module 1(GPS 궤적)과 연결해 스케일을 실측 기반으로 고정하면 오차가
  더 줄어들 것으로 예상.
